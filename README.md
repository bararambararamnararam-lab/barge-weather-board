# 한·중 바지선 운항 기상 조회 시스템

거제 고현항과 중국 산둥·장쑤 항만을 오가는 바지선 항로의 기상·해양 예보를
위치별·시간별로 한 화면에서 보는 프로그램이다.

이 폴더에는 **더블클릭해서 쓰는 파일 5개**가 있다. 이것만 알면 된다.

| 파일 | 언제 쓰나 | 하는 일 |

| `0_처음설치.bat` | **딱 한 번만** | 프로그램 실행에 필요한 것들을 자동으로 깐다 |
| `1_수집하기.bat` | 데이터를 지금 당장 받고 싶을 때 | 예보 + 기상특보를 받아 저장하고 웹 자료까지 만든다 |
| `3_자동수집_시작.bat` | 계속 자동으로 모으고 싶을 때 | 창을 켜 두면 3시간/30분마다 알아서 수집 |

| `2_화면열기.bat` | PC 에서 깊게 파볼 때 | 예전 Streamlit 화면 (과거 실황·예보 이력 등) |

### 처음 시작하는 순서

1. `0_처음설치.bat` 더블클릭 → 설치가 진행된다. 끝나면 아무 키나 누른다.
2. `1_수집하기.bat` 더블클릭 → 1~2분 기다린다.
3. `4_폰_PC_웹화면_시작.bat` 더블클릭 → 검은 창에 주소가 나온다.
4. PC 브라우저에서 `http://localhost:8080` 을 연다.

**검은 창을 닫으면 화면도 꺼진다.** 켜 둔 채로 둔다.

### 폰에서 보기

`4_폰_PC_웹화면_시작.bat` 을 켜면 검은 창에 이런 주소들이 나온다.

```
이 컴퓨터에서 :  http://localhost:8080
다른 기기에서 :  http://100.x.x.x:8080  (Tailscale)
다른 기기에서 :  http://192.168.x.x:8080
```
(실제로는 뒤 숫자 자리에 내 컴퓨터의 진짜 주소가 나온다. 매번 자동으로 찾아서 보여 주는 것이라 아무나 미리 알 수 없다.)

- **같은 Wi-Fi 안에서**: `192.168.` 로 시작하는 주소를 폰 브라우저에 친다.
- **밖에서(LTE)**: 인터넷에 올려야 한다. 아래 12절을 본다.

**폰 홈 화면에 앱처럼 두기**

- 아이폰: 사파리로 열고 → 공유 버튼 → `홈 화면에 추가`
- 안드로이드: 크롬으로 열고 → 메뉴 → `홈 화면에 추가`

주소창 없이 앱처럼 열린다.

## 1. 이 프로그램이 하는 일

- 항로에 있는 지점(기상을 보는 곳 15곳)의 기상·해양 예보를 **최대 10일 앞까지** 받는다.
  (가까운 3일은 3시간 간격, 그 뒤는 6시간 간격)
- 받은 예보를 **지울 수 없는 기록(스냅샷)** 으로 계속 쌓는다.
  나중에 "그때 예보가 어땠는지" 를 다시 볼 수 있다.
- 값이 위험 기준을 넘으면 **초록/노랑/빨강/회색** 으로 칠한다.
- 각 칸에 마우스를 올리면 **왜 그 색인지 근거**가 뜬다.
- 기상청 특보(풍랑·강풍·태풍 등)를 같이 보여 준다.
- **지금 이 지점에 있는 배가 목적지까지 몇 시간 걸릴지** 계산한다(아래 1-3절).

### 이 프로그램이 하지 않는 일

- 항로 전체를 하나의 "출항 가능/불가" 로 합치지 않는다.
- 자동으로 출항을 승인하지 않는다. **최종 판단은 담당자가 한다.**
- 중국 관할 해역의 기상특보는 다루지 않는다(기상청 API 범위 밖).

>
> 화면 폭을 아끼려고 이름은 모두 짧게 유지한다(최대 9자).
> 긴 설명은 `weather_config.yaml` 의 주석에 남겨 뒀다.

## 1-2. 웹 화면 (폰 · PC 공용)

`4_폰_PC_웹화면_시작.bat` 으로 띄우는 기본 화면이다.
폰과 PC 가 **같은 주소, 같은 코드**를 쓰고 화면 폭에 따라 모양만 바뀐다.

### 아래쪽 탭 4개

| 탭 | 내용 |
| --- | --- |
| 목록 | 지점 카드가 세로로. **한 장이 두 줄**이다.<br>1줄 = 번호·이름·특보·판정 / 2줄 = 풍속·돌풍·파고·풍향 |
| 지도 | OpenStreetMap 위에 항로·지점 + **해역 색칠** |
| 표 | 위치 × 시간 격자 (PC 에서 특히 유용) |
| 특보 | 지점별 발효 중인 특보 + 전국 목록 |

### 맨 위 조작부

- **영성 / CSME** — 항로를 고른다.
- **시각 막대** — 밀면 그 시각의 상태로 전부 바뀐다. `‹` `›` 로 한 시간씩, `지금` 으로 현재로.
- **↻** — 새로 수집된 자료를 다시 읽는다.

### 지점 카드를 누르면

그 지점의 **시간별 목록**으로 들어간다.
위쪽 칩으로 운항 판단 / 평균 풍속 / 순간 풍속 / 유의파고 / 시정 / 강수 / 해류를 바꿔 본다.
현재 시각 줄에는 파란 테두리가 있다.

### 화면이 알아서 바뀌는 것

- **어두운 모드**: 폰이나 PC 가 어두운 모드면 화면도 어두워진다.
- **가로/세로**: 돌리면 다시 맞춘다.
- **넓은 화면(900px 이상)**: 아래 탭이 위로 올라가고 격자 표가 넓게 나온다.

### 해역 색칠 (지도 탭)

기상청 특보 지도처럼 **바다를 면으로 칠한다.** 지점 15곳의 점만으로는
"항로 중간이 지금 어떤지" 를 알기 어려워서 넣었다.

- 바다를 약 **28 km 칸**으로 나누고 칸마다 초록/노랑/빨강을 칠한다
- 시각 막대를 밀면 색이 그 시각으로 바뀐다
- 왼쪽 위 `해역 색칠 켜짐` 을 누르면 끄고 켤 수 있다

> ### ⚠️ 점과 면은 기준이 다르다
>
> | | 계산에 쓰는 것 |
> | --- | --- |
> | **지점 동그라미** (1~9) | 풍속·돌풍·파고·시정·강수·뇌우 + **기상청 특보** |
> | **바다 색칠** | 풍속·돌풍·파고·시정 **만** (특보 제외) |
>
> 왜 다른가: 기상청이 특보구역의 **경계 좌표를 공개하지 않는다.**
> 그래서 임의의 바다 좌표가 어느 특보구역에 드는지 알 수가 없다.
> 지점 15곳은 사람이 직접 구역을 지정해 뒀지만(`kma_zones`), 격자 칸은 못 한다.
>
> 그래서 **동그라미가 빨강인데 주변 바다는 초록**일 수 있다.
> 특보 때문에 빨강이 된 경우다. 최종 판단은 동그라미(지점) 기준으로 본다.

**만드는 방법 (개발자용)**

| 단계 | 내용 |
| --- | --- |
| 날씨 값 | 지점 15곳을 뽑을 때 **같은 파일에서 같이 뽑는다**. 추가 다운로드가 0 이다 |
| 그리는 칸 | 0.25° (약 28 km). ECMWF 격자 간격과 같다. 약 950칸 |
| 육지 제외 | 표고(땅 높이)를 칸마다 받아 0 m 이하만 칠한다 |
| 마스크 저장 | 표고는 변하지 않으므로 `data/grid_mask.json` 에 저장해 두고 재사용 |

추가 다운로드가 없는 이유: ECMWF 는 "이 지역만 잘라 달라"를 안 해 준다.
어차피 전 지구 파일을 통째로 받으므로, 그 안에 우리 바다 칸이 이미 다 들어 있다.
지점 값을 꺼낼 때 격자 칸도 같이 꺼내면 끝이다.

설정은 `weather_config.yaml` 의 `grid:` 에서 바꾼다.

```yaml
grid:
  enabled: true        # false 로 두면 바다 색칠을 안 만든다
  mask_step_deg: 0.25  # 그리는 칸 크기(도). 0.25 = 약 28 km
  margin_deg: 1.0      # 항로 바깥으로 얼마나 더 넓게 볼지(도)
```

## 1-3. 소요 시간 (ETA)

지점 카드를 누르면 맨 위에 **"이 지점에서 출발하면 얼마나 걸리는지"** 가 나온다.

```
09/07 00:00 에 이 지점에서 출발하면
 앞으로    영성법인 (415해리)  바지선 89시간 · 9/10(목) 17시 도착 · 대기 4시간
                              자항선 81시간 · 9/10(목) 09시 도착 · 대기 21시간
 돌아가기  거제 고현항 (21해리) 바지선 5시간 · 9/7(월) 05시 도착
```

**어떻게 계산하나**

배를 한 시간씩 전진시키면서, 그 시각·그 구간의 운항 판단을 본다.

| 구간 판정 | 속력 |
| --- | --- |
| 가능(초록) | 기준 속력 그대로 |
| 조건부(노랑) | 기준 속력 × 0.75 |
| 불가(빨강) | **멈추고 기다린다** (기상이 나아질 때까지) |

핵심은 **지나가는 시각의 예보를 그때그때 반영**한다는 점이다.
배가 진도 남방을 지날 때는 출발로부터 30시간쯤 뒤이므로, 지금 기상이 아니라
그때의 예보를 본다. 그래서 **빠른 배가 오히려 더 오래 기다리는 일도 생긴다**
(나쁜 기상 구간에 일찍 도착해 버리는 경우).

**배 종류 2가지**

| 종류 | 기준 속력 | 고현~영성(415해리) | 실제 운항 기록 |
| --- | --- | --- | --- |
| 예인선+바지선 | 6.5 노트 | 63.8시간 | 월 17시 출항 → 목 08:47 (3일째 아침) ✓ |
| 자항선 | 9.0 노트 | 46.1시간 | 48시간 전후 ✓ |

두 값 모두 **실제 운항 기록과 맞춰 확인했다.**

`weather_config.yaml` 의 `voyage:` 에서 고친다. 속력, 감속 비율,
불가 구간에서 기다릴지 통과할지를 모두 바꿀 수 있다.

**길을 꺾는 점**

고현항에서 거제 동방으로 직선을 그으면 **거제도 육지를 뚫는다.**
실제로는 북쪽으로 나가 거제도 위를 돌아 내려간다. 그 모양을 만들려고
`고현 북방`·`거제 북방` 두 점을 넣어 뒀다(`geometry_only: true`).

이 두 점은 거리 계산과 지도 선에만 쓰고 **기상은 받지 않는다.**
좁은 내만이라 따로 볼 이유가 없고, 목록·표에도 나오지 않는다.
이 우회를 반영해서 고현항~영성 거리가 404 → **415 해리**가 됐다.

### 자료 흐름

```
1_수집하기.bat  또는  3_자동수집_시작.bat
        │
        ├─ ECMWF·NOAA·met.no / 기상청 → SQLite (data/weather.db)
        └─ SQLite → web/data/*.json      ← 수집할 때마다 자동
                          │
        4_폰_PC_웹화면_시작.bat 이 web/ 폴더를 그대로 내보낸다
                          │
                    폰 / PC 브라우저
```

`web/` 폴더는 **파이썬 없이도 도는 정적 사이트**다.
그래서 그대로 인터넷에 올릴 수 있다(12절).

전송량은 처음 한 번 **약 54 KB**(압축 기준)다. LTE 로도 부담 없다.

## 2. 화면 보는 법

### 왼쪽 사이드바

| 항목 | 설명 |
| --- | --- |
| 항로 | 영성 / CSME 중 선택. 그 항로에 속한 지점만 표에 나온다 |
| 시간 간격 | 3시간(기본) 또는 1시간. 1시간은 열이 3배로 늘어난다 |
| 몇 일치를 볼지 | 1~10일 |
| 데이터 새로고침 | 방금 수집한 데이터를 화면에 바로 반영한다 |
| 최근 수집 기록 | 수집이 언제 성공/실패했는지 보여 준다 |
| 원본/아카이브/실황 행 수 | 지금 저장돼 있는 데이터 양 |

### 표 위의 지도 (OpenStreetMap)

표 위에 `지도로 보기` 를 펼치면 선택한 항로가 지도에 그려진다.

| 지도에 있는 것 | 뜻 |
| --- | --- |
| 파란 점선 | 항해 순서대로 이은 항로. 끝에서 갈라지면 가지로 뻗는다 |
| 동그라미 | 지점. 색은 표와 같은 초록/노랑/빨강/회색 |
| 동그라미 옆 숫자 | **표의 행 번호와 같다.** 지도 `3` = 표 `3. 여수 남방 해상` |
| 짧은 막대 | 바람이 **불어 가는** 방향. 길수록 강한 바람 |
| 왼쪽 아래 배지 | 지금 지도가 보여 주는 시각과 항목 |

**조작**

- `지도에 표시할 시각` 을 밀면 그 시각의 상태로 지도가 바뀐다.
- `표시 항목` 에서 운항 판단 / 평균 풍속 / 순간 풍속 / 유의파고 / 시정 중 고른다.
- **동그라미를 누르면** 그 칸의 판정 근거가 전부 뜬다(표 툴팁과 같은 내용).
- 확대·축소는 왼쪽 위 `+` `−` 버튼. 끌어서 이동할 수 있다.
- 제목 줄 `지도로 보기` 를 누르면 지도를 접을 수 있다.

> 지도 타일은 OpenStreetMap 서버에서 받아 온다. **인터넷이 필요하다.**
> 인터넷이 안 되면 지도 자리에 안내 문구가 뜨고, 아래 표는 그대로 동작한다.
>
> Streamlit 의 기본 지도 명령(`st.map`, `st.pydeck_chart`)은 OpenStreetMap 이
> 아니라 Carto 타일을 쓴다. pydeck 에 OSM 타일을 붙여 봤으나 화면에 뜨지
> 않아, OSM 공식 뷰어인 Leaflet 을 직접 띄우는 방식으로 만들었다.

## 3. 알아 둬야 할 한계 3가지

### (1) 예보는 10일까지다

예보 범위를 **10일**로 잡아 뒀다. 세계 어느 기상청이든 그 뒤로는
숫자는 나와도 맞을 확률이 크게 떨어져서, 보여 줄 값어치가 없다.

예전에는 14일까지 표를 그렸는데 8일차부터 파고가 비어서
표 절반이 회색이었다. 그래서 아예 10일로 줄였다.

앞 3일은 3시간 간격, 그 뒤는 6시간 간격이다.
먼 날짜는 추세만 보면 되므로 촘촘히 받을 이유가 없다.

### (2) 중국 쪽 기상특보는 없다

기상청 특보는 한국 관할 구역만 다룬다.
중국 해역·항만 지점은 **특보 표시가 비어 있는 것이 정상**이다.
이 지점들의 판단은 숫자 값만으로 한다.

이어도 북동방은 한중 중첩수역이라 기상청 먼바다 구역 밖이다.
한국이지만 특보가 없다.

**지점별 특보구역 (config/weather_config.yaml 의 `kma_zones`)**

| 지점 | 구역 코드 | 구역명 | 확도 |
| --- | --- | --- | --- |
| 거제 고현항 | `S1311300` | 경남중부남해앞바다 | 보통 |
| | `S2320800` | 〃 중 연안바다 | 보통 |
| | `L1082200` | 거제시 (육상) | 확실 |
| 거제 동방 | `S1311400` | 거제시동부앞바다 | **확실** |
| 여수 남방 | `S1312010` | 남해동부안쪽먼바다 | 경계 |
| 진도 남방 | `S1322100` | 남해서부서쪽먼바다 | 보통 |
| 흑산도 북방 | `S1232210` | 서해남부남쪽안쪽먼바다 | 보통 |
| 서해 남부 먼바다 | `S1232120` | 서해남부북쪽바깥먼바다 | 경계 |
| 제주해협 | `S1323100` | 제주도북부앞바다 | 경계 |
| 중국 지점 · 이어도 북동방 | — | 없음 | — |

> **확도 표시의 뜻**: 기상청이 특보구역의 경계 좌표를 공개하지 않는다.
> 그래서 위 배정은 좌표로 추정한 값이다.
> `확실` = 구역 이름이 그 위치를 그대로 가리킴.
> `보통` = 경계에서 떨어져 있어 대체로 맞음.
> `경계` = 두 구역 경계 부근이라 확인이 필요함.
>
> 실제 특보와 어긋나면 `weather_config.yaml` 의 `kma_zones` 목록만 고치면 된다.
> 실제 조회에서 거제 동방·여수 남방·진도 남방·제주해협 네 곳은
> 풍랑주의보가 정상적으로 잡히는 것을 확인했다.

### (3) 한계값은 아직 확정된 값이 아니다

`config/weather_config.yaml` 의 숫자는 **화면 경보용 초안**이다.
자동 출항 승인 기준도, 법정 운항 한계도 아니다.
선박별 안전관리매뉴얼과 항만/VTS 지시로 반드시 재검토해야 한다.

현재 초기값:

| 항목 | 노랑(주의) | 빨강(불가) |
| --- | --- | --- |
| 평균 풍속 | 10.0 m/s 이상 | 12.0 m/s 이상 |
| 순간 풍속 | 14.0 m/s 이상 | 16.0 m/s 이상 |
| 유의파고 | **1.5 m 이상** | **2.5 m 이상** |
| 시정 | 3.0 km 미만 | 1.852 km(1해리) 미만 |
| 시간 강수량 | 5.0 mm 이상 | (불가 판정 안 함) |
| 뇌우 지수 CAPE | 1000 J/kg 이상 | (불가 판정 안 함) |
| 해류 | 자동 판정 안 함 (숫자만 표시) | — |

특보 반영:

| 특보 수준 | 판정 |
| --- | --- |
| 예비 | 조건(노랑) |
| 주의(주의보) | 조건(노랑) |
| 경보 | 불가(빨강) |
| 태풍 (수준 무관) | 불가(빨강) |
| 황사·폭염·한파·건조 | 판정에서 무시 (화면에는 계속 표시) |

#### 파고 기준을 왜 0.5/1.0 에서 1.5/2.5 로 올렸나

처음 값 0.5 / 1.0 m 는 OILHUB 터미널의 **접안·하역** 제한에서 가져온 것이었다.
항로 중간 해상 지점을 넣고 실제 예보를 조회해 보니, 그 기준으로는
항해 구간 대부분이 상시 빨강이 되어 경보로서 의미가 없었다.

| 지점 | 파고 최소 | 1.0 m 기준일 때 빨강 비율 |
| --- | ---: | ---: |
| 얀다항 동방 해상 | 0.90 m | 88% |
| 이어도 북동방 해상 | 0.72 m | 70% |
| 제주해협 | 0.30 m | 56% |
| 서해남부 먼바다 | 0.20 m | 40% |

얀다항 동방 해상은 예보 기간 내내 파고가 0.9 m 아래로 내려가지 않는다.
즉 그 칸은 **영원히 빨강**이다.

1.5 / 2.5 로 올린 뒤:

| 지점 | 불가 칸 수 (변경 전 → 후) |
| --- | --- |
| 얀다항 동방 해상 | 199 → **0** |
| 이어도 북동방 해상 | 157 → **2** |
| 제주해협 | 125 → **6** |
| 서해남부 먼바다 | 91 → **0** |
| 흑산도 북방 해상 | 49 → **0** |

이제 빨강은 실제로 험한 구간에만 뜬다.

> ### ⚠️ 대신 생긴 한계
>
> 1.5 / 2.5 는 **항해 중 기준**이다. 항만 접안·하역 기준이 아니다.
> 고현항·얀다항에서 실제로 접안하거나 화물을 다룰 때는
> 이 화면 색만 보지 말고 해당 터미널·VTS 기준을 따로 확인해야 한다.
>
> 접안 지점만 다시 엄격하게 하려면 지점 종류(`type`)별로 한계값을
> 나누는 작업이 필요하다. 지금은 전 지점에 같은 값을 쓴다.

## 4. 설정 바꾸는 법

`config/weather_config.yaml` 파일을 **메모장**으로 열어서 고치고 저장하면 된다.
프로그램 코드는 건드릴 필요가 없다. 고친 뒤 화면에서 `데이터 새로고침` 을 누른다.

### 지켜야 할 규칙 3가지

1. 들여쓰기는 **공백(스페이스) 2칸**. **Tab 키를 쓰면 안 된다.**
2. 콜론(`:`) 뒤에는 항상 공백 1칸.
3. `#` 으로 시작하는 줄은 설명이라 프로그램이 무시한다.

### 예: 파고 주의 기준을 1.5 → 2.0 m 로 올리기

```yaml
  wave_height_m:
    caution_at: 2.0        # <- 이 숫자만 고친다
    unavailable_at: 2.5
```

### 예: 항로 중간 해상 지점 추가하기

1단계 — `locations:` 밑에 지점을 추가한다.

```yaml
  R1_WP_NEW:
    name: "새 지점 이름"
    latitude: 35.500000
    longitude: 126.500000
    type: route_waypoint
    country: KR
    kma_zones: []          # 한국 해역이면 특보구역 코드를 넣는다
```

2단계 — `routes:` 의 해당 항로 `waypoints:` 에 그 ID를 항해 순서대로 넣는다.

```yaml
  R1:
    name: "고현항 → 리따오 묘박지 → 삼성중공업 영성법인"
    endpoints: [GOHYEON, LIDAO_ANCH, SAMSUNG_YR]
    waypoints: [GEOJE_E, YEOSU_S, R1_WP_NEW, JINDO_S, HEUKSAN_N, SEOHAE_S, SHIDAO_E]
```                                        # ↑ 항해 순서에 맞는 자리에 끼워 넣는다

3단계 — `1_수집하기.bat` 을 다시 실행한다.

> **주의**: 두 지점을 직선으로 이어 중간점을 찍으면 육지를 통과할 수 있다.
> 반드시 실제로 배가 지나가는 바다 위 좌표만 넣는다.

## 5. 자동 수집

`3_자동수집_시작.bat` 을 더블클릭하면 창이 하나 뜨고 계속 켜져 있다.

- 예보: 3시간마다
- 기상특보: 30분마다

**이 창을 닫으면 자동 수집이 멈춘다.** 컴퓨터를 켜 둔 채로 두면 된다.

주기를 바꾸려면 `config/weather_config.yaml` 의 이 부분을 고친다.

```yaml
collection:
  forecast_interval_minutes: 180   # 예보 주기(분)
  warning_interval_minutes: 30     # 특보 주기(분)
```

### 컴퓨터 켤 때 자동으로 시작시키기 (선택)

1. `Win + R` → `shell:startup` 입력 → 엔터
2. 열린 폴더에 `3_자동수집_시작.bat` 의 **바로가기**를 만들어 넣는다.

## 6. 데이터가 어디에 쌓이나

```
claude-weather\data\weather.db      <- 모든 데이터가 이 파일 하나에 들어 있다
claude-weather\data\export\         <- 엑셀로 내보낸 파일들
```

`weather.db` 하나만 복사해 두면 전체 백업이 된다.

### 저장을 3단계로 나눈 이유

지점을 20곳까지 늘리면 데이터를 그냥 다 쌓을 수 없다.
그래서 **오래될수록 성기게** 남기는 구조로 만들었다.

| 단계 | 무엇 | 항목 | 시간 간격 | 예보 범위 | 보관 |
| --- | --- | --- | --- | --- | --- |
| 1. 원본 | 3시간마다 수집한 것 전부 | 9개 | 3~6시간 | 10일 | **7일** |
| 2. 아카이브 | 하루 1개(09시 근방)만 | 7개 | 3시간 | 7일 | **1년** |
| 3. 실황 | 수집 시점의 현재값 | 9개 | 3시간 | — | **2년** |
| 특보 | 기상청 특보 기록 | — | — | — | **2년** |

- **화면에 지금 보이는 표는 항상 1단계**에서 나온다. 늘 최신이다.
- 하루가 지나면 그날 09시 수집분 하나를 골라 2단계로 줄여 넣고,
  7일이 지난 1단계 원본은 지운다. 이 순서는 자동이고 어긋나지 않는다.
- 컴퓨터를 며칠 꺼 뒀다 켜도 빠진 날을 알아서 채운다.

**아카이브에 남기는 7개 항목**: 평균 풍속, 풍향, 순간 풍속, 시정, 유의파고,
운항 판단, 기상특보 요약.

순간풍속과 시정을 같이 남기는 이유는 **나중에 한계값을 고쳤을 때 과거 판정을
새 기준으로 다시 계산할 수 있게** 하기 위해서다. 화면은 지금 한계값으로 다시
계산한 색을 보여 주고, 툴팁에는 `저장 당시 판정`도 같이 나온다.

아카이브에 **없는 항목**(강수, 파주기)은 회색으로 나온다.

### 용량 (지점 20곳 · 1년 운영 기준, 실측)

| 항목 | 행 수 | |
| --- | ---: | --- |
| 1단계 원본 (7일) | 59,360 | |
| 2단계 아카이브 (1년) | 416,100 | |
| 3단계 실황 (2년) | 116,800 | |
| 특보 (2년) | 21,823 | |
| **합계 파일 크기** | | **약 140 MB** |

행 하나가 약 366 바이트인 것을 실제로 재서 계산한 값이다.
처음(1시간 간격·14일)에는 같은 조건에서 약 1,690 MB였다. 12배 줄었다.

**한 달 인터넷 사용량은 약 37 GB**다. 대부분이 ECMWF 전 지구 파일
(한 벌 약 310 MB × 하루 4번)이다. 깃허브에서 돌리면 내 인터넷은 안 쓴다.

특보는 30분마다 조회하지만 **내용이 같으면 다시 쌓지 않는다.**
같은 특보는 한 줄로 두고 `마지막으로 본 시각`만 갱신한다.
(안 그러면 2년에 168만 행 = 252 MB가 된다.)

### 보존 기간 바꾸기

`config/weather_config.yaml`:

```yaml
retention:
  raw_snapshot_days: 7        # 1단계 원본
  archive_days: 365           # 2단계 아카이브
  observation_days: 730       # 3단계 과거 실황
  warning_days: 730           # 기상특보 기록
  vacuum_every_n_runs: 24     # 지운 자리를 파일에서 회수하는 주기
```

`null` 을 넣으면 그 종류는 지우지 않는다(영구 보관).

> SQLite 는 데이터를 지워도 파일 크기가 바로 줄지 않는다.
> `vacuum_every_n_runs` 횟수마다 한 번씩 빈 자리를 실제로 회수한다.
> 이때 몇 초 멈춘다. `0` 을 넣으면 회수하지 않는다.

### 아카이브 규칙 바꾸기

```yaml
archive:
  target_hour: 9       # 하루 중 어느 시각 수집분을 남길지 (한국시간)
  hour_window: 6       # 목표에서 이만큼 벗어난 것까지 허용. 넘으면 그날은 건너뜀
  forecast_days: 7     # 아카이브에 담을 예보 범위
  step_hours: 3        # 아카이브 시간 간격
```

| 8080 포트가 이미 사용 중 | 이미 떠 있는 창을 닫는다. 또는 `python -m weather.serve 9000` |

## 8. 데이터 출처와 라이선스

| 데이터 | 어디서 | 라이선스 | 상업 사용 |
| --- | --- | --- | --- |
| 바람·돌풍·파고·파향·파주기·강수 | 유럽중기예보센터 ECMWF Open Data (IFS / WAM) | CC BY 4.0 | **가능** (출처만 밝히면 됨) |
| 시정 | 미국 해양대기청 NOAA GFS | 미국 공공저작물 | **가능** (조건 없음) |
| 바람 (매시간 덮어쓰기) | 노르웨이 기상청 MET Norway | CC BY 4.0 | **가능** (연락처 표기 필요) |
| 기상특보 | 대한민국 기상청 API 허브 | 공공데이터 | **가능** |
| 지도 배경 | OpenStreetMap | ODbL | **가능** (출처 표기, 화면에 이미 있음) |

화면 아래와 엑셀 파일에 출처 문구가 자동으로 들어간다:
`Data from ECMWF (CC BY 4.0), NOAA GFS, MET Norway (CC BY 4.0), KMA`

### 왜 자료원을 바꿨나 (2026-09-06)

처음에는 Open-Meteo 한 곳에서 다 받았다. 편했지만 **무료 API 는
비상업적 용도만** 허용된다. 실제 회사 배선 업무에 쓰는 순간 위반이다.

그래서 ECMWF(유럽) + NOAA(미국) + MET Norway(노르웨이) 세 곳으로 갈아탔다.
셋 다 국가 기관이 세금으로 만들어 무료로 푸는 자료라 회사 업무에 써도 된다.

바뀌면서 **없어진 항목**: 해류, 수온, 기상코드, 뇌우지수(CAPE).
세 곳 다 주지 않는 값이라 화면에서 뺐다. 운항 판단에는 쓰지 않던 값들이다.

### 역할 나누기

- **ECMWF** — 뼈대. 하루 4번(00·06·12·18 UTC) 모델이 돈다. 새로 나왔을 때만 받는다.
- **NOAA** — 시정만. ECMWF 가 시정을 안 준다. NOAA 는 지역을 잘라 줘서 가볍다.
- **MET Norway** — 바람만. 매시간 갱신되므로 ECMWF 바람 위에 덮어쓴다.
  가까운 시간의 바람이 더 최신이 된다.

기상청 API 허브 키는 `.env` 파일에만 넣는다. 이 파일은 `.gitignore` 에 들어 있어
git 에 올라가지 않는다. **키를 코드나 문서에 직접 적지 않는다.**

> **그림으로 보는 설명서**: `배포_설명서.html` 파일을 더블클릭하면 브라우저로
> 열린다. 아래 내용을 체크리스트 형태로 단계별로 따라갈 수 있게 정리해 뒀다.

두 가지 방식이 있다.

| 방식 | 내 PC | 자료 최신 유지 | 난이도 |
| --- | --- | --- | --- |
| **A. 깃허브가 대신 수집** (권장) | **꺼도 됨** | 하루 4번 자동 | 처음 30분 |
| B. 내 PC 가 수집하고 화면만 올리기 | 켜져 있어야 함 | 올릴 때마다 | 10분 |

### A. 깃허브 액션으로 자동 돌리기 (권장)

깃허브가 빌려주는 리눅스 컴퓨터가 하루 4번 잠깐 켜져서
자료를 받고 화면을 갱신한다. **내 컴퓨터는 꺼져 있어도 된다.** 무료다.

설정 파일은 이미 만들어져 있다: `.github/workflows/collect.yml`

#### 한 번만 하면 되는 준비

**1) 깃허브 계정 만들고 저장소 만들기**

[github.com](https://github.com) 가입 → 오른쪽 위 `+` → `New repository`
→ 이름 아무거나(예: `weather`) → **Private** 선택 → `Create`

> Private 로 해도 GitHub Pages 화면은 뜬다. 소스만 안 보이게 된다.

**2) 이 폴더를 올린다**

명령 프롬프트를 `claude-weather` 폴더에서 열고:

```
git init
git add .
git commit -m "첫 등록"
git branch -M main
git remote add origin https://github.com/<내계정>/weather.git
git push -u origin main
```

`.env`(기상청 키)와 `data/`(데이터베이스)는 `.gitignore` 때문에
**자동으로 빠진다.** 키가 깃허브에 올라가지 않는다.

**3) 기상청 키를 깃허브 금고에 넣는다**

저장소 → `Settings` → `Secrets and variables` → `Actions`
→ `New repository secret`

- Name: `KMA_HUB_API_KEY`
- Secret: `.env` 파일 안에 있는 키 값

> 금고에 넣은 값은 깃허브 화면에서도 다시 볼 수 없고, 로그에도 `***` 로 가려진다.

**4) 웹페이지 켜기**

저장소 → `Settings` → `Pages` → `Source` 를 **`GitHub Actions`** 로 바꾼다.
(`Deploy from a branch` 가 아니다. 꼭 바꿔야 한다.)

**5) 한 번 손으로 돌려 본다**

저장소 → `Actions` 탭 → 왼쪽 `기상자료 수집` → 오른쪽 `Run workflow`

5~8분 뒤 초록 체크가 뜨면 성공이다. 주소는 다음과 같다:

```
https://<내계정>.github.io/weather/
```

#### 자동으로 도는 것 2가지

| 워크플로 | 언제 도나 | 하는 일 | 걸리는 시간 |
| --- | --- | --- | --- |
| **기상자료 수집** | 하루 4번 (아래 표) + 손으로 | 새 예보를 받아 DB에 넣고 화면까지 배포 | 약 1분 |
| **화면 배포** | `web/`·`src/`·`config/` 를 고쳐 올릴 때마다 | 자료는 그대로 두고 화면만 다시 만들어 배포 | 약 30초 |

두 번째가 있는 이유: `git push` 는 코드를 깃허브에 올릴 뿐이라
사이트는 그대로였다. 화면을 고쳐도 다음 수집 때까지 반영이 안 됐다.
이제는 올리기만 하면 알아서 다시 배포된다.

#### 기상자료 수집은 이때 돈다

| 한국시간 | 무슨 자료 |
| --- | --- |
| 05:15 | 전날 12 UTC 모델 |
| 09:15 | 전날 18 UTC 모델 |
| 17:15 | 당일 00 UTC 모델 |
| 21:15 | 당일 06 UTC 모델 |

시각을 바꾸려면 `.github/workflows/collect.yml` 의 `cron:` 줄을 고친다.
`- cron: "15 8 * * *"` 는 **UTC 기준 8시 15분** = 한국시간 17시 15분이다.

#### 자료가 어디에 쌓이나

| 무엇 | 어디에 | 지금 크기 | 한도 |
| --- | --- | --- | --- |
| 소스 코드 | 저장소 | 약 1 MB | 1 GB 넘으면 경고 |
| 과거 기록 전부 (SQLite) | Releases 의 `weather.db.gz` | 0.04 MB | 파일 하나당 2 GB |
| 화면 (web 폴더) | GitHub Pages | 약 0.9 MB | 사이트 1 GB, 월 전송 100 GB |
| 실행 시간 | Actions | 하루 4회 × 8분 | 공개 저장소는 무제한 |

DB 는 `Releases` 칸에 파일 하나로 보관되고 매번 덮어쓰므로 이력이 쌓이지 않는다.
받아서 내 PC 의 `data/weather.db` 자리에 풀어 넣으면 그대로 이어서 쓸 수 있다.

**화면용 JSON(`web/data/*.json`)은 저장소에 커밋하지 않는다.**
사이트는 저장소 파일이 아니라 자동수집이 만든 '배포 꾸러미'에서 서비스되기 때문에
커밋할 이유가 없다. 굳이 커밋하면 `grid.json`(786 KB)이 하루 4번 통째로 바뀌면서
저장소가 1년에 300~400 MB 씩 불어나고, 내 컴퓨터와 어긋나 `git pull` 충돌이 난다.

#### 무료 한도 걱정 안 해도 되나

- 공개(Public) 저장소: Actions **무제한 무료**
- 비공개(Private) 저장소: 월 2,000분 무료. 우리는 한 번에 약 8분 × 하루 4번
  = **월 약 960분**. 절반쯤 쓴다.

인터넷 사용량(월 37 GB)은 깃허브 쪽에서 나가므로 내 요금과 상관없다.

### B. 화면만 올리기 (수집은 내 PC)

`web/` 폴더는 **그 자체로 완성된 정적 사이트**다. 파이썬도 데이터베이스도 필요 없다.

- **Cloudflare Pages**: [dash.cloudflare.com](https://dash.cloudflare.com) →
  `Workers & Pages` → `Create` → `Pages` → `Upload assets` →
  `claude-weather\web` 폴더를 통째로 끌어다 놓는다
- **Netlify**: [app.netlify.com/drop](https://app.netlify.com/drop) 에
  `web` 폴더를 끌어다 놓는다 (`netlify.toml` 이 이미 설정돼 있다)

단, **올린 시점의 자료로 멈춰 있다.** 갱신하려면 다시 올려야 한다.
`wrangler pages deploy web` 을 `3_자동수집_시작.bat` 뒤에 붙이면 자동이 된다.

### ⚠️ 아무나 볼 수 있게 된다

정적 사이트에는 **진짜 암호를 걸 수 없다.** 화면에 암호창을 붙여도
`주소/data/forecast.json` 을 직접 치면 자료가 그대로 나온다.
브라우저에서 도는 코드는 누구나 열어볼 수 있기 때문이다.

제대로 막으려면 호스팅 쪽에서 막아야 한다.

| 방법 | 비용 | 보호 수준 |
| --- | --- | --- |
| **Cloudflare Pages + Cloudflare Access** | 무료(50명까지) | 접속 전에 이메일 인증. 자료 파일까지 전부 막힌다 |
| GitHub Pages (Private 저장소) | 무료 | **주소를 아는 사람은 누구나 본다.** 저장소만 비공개 |
| Netlify 유료 (Pro) | 월 $19 | 사이트 전체 암호 |
| 주소만 안 알려주기 | 무료 | **보호 아님.** 주소가 새면 끝 |

`web/robots.txt` 와 `_headers` 에 검색엔진 차단은 넣어 뒀지만,
그건 검색에 안 잡히게 할 뿐 접근을 막지는 못한다.

우리 화면에 있는 것은 공개된 기상 자료와 항로 지점 좌표뿐이라
새어 나가도 큰일은 아니다. 다만 **항로 좌표는 회사 영업 정보**이므로,
남에게 보이기 싫다면 Cloudflare Access 를 쓰는 편이 낫다.

> **주의**: 어느 방법이든 `.env` 의 기상청 API 키는 절대 올리지 않는다.
> 키는 수집하는 쪽(내 PC 또는 깃허브 금고)에만 있으면 되고,
> 웹 화면은 이미 만들어진 JSON 만 읽는다. `web/` 폴더 안에는 키가 들어가지 않는다.

---

### 밖에서 보는 다른 방법 (배포 없이)

PC 에 **Tailscale 이 이미 깔려 있다면**, 폰에도 Tailscale 앱을 깔고
같은 계정으로 로그인한다. 그러면 `4_폰_PC_웹화면_시작.bat` 검은 창에 뜨는
`100.` 으로 시작하는 주소로 LTE 에서도 바로 들어갈 수 있다.

- 공유기 설정이나 포트 개방이 필요 없다
- 인터넷에 공개되지 않는다 (내 기기끼리만)
- 무료이고, 자료가 항상 최신이다
- 대신 **PC 가 켜져 있어야 한다**

### 데이터베이스 테이블

| 테이블 | 내용 | 기본 키 |
| --- | --- | --- |
| `forecast_snapshot` | 1단계 원본 스냅샷 (7일) | `(collected_at, location_id, valid_time)` |
| `forecast_archive` | 2단계 아카이브 (1년) | `(archive_date, location_id, valid_time)` |
| `observation` | 3단계 과거 실황 (2년) | `(observed_at, location_id)` |
| `kma_warning` | 기상청 특보, 중복 제거 (2년) | `(reg_id, wrn, tm_fc, tm_ef, lvl, cmd, ed_tm)` |
| `collection_run` | 수집 실행 기록 | `(started_at, kind)` |

예보 표는 `INSERT OR IGNORE` 만 쓴다. 한 번 저장한 스냅샷은 덮어쓰지 않는다.
특보 표만 예외로, 같은 특보를 다시 보면 `last_seen` 을 갱신한다(중복 제거).

옛 구조(`kma_warning` 에 `collected_at` 이 있던 형태)로 만든 파일은
프로그램을 켤 때 자동으로 새 구조로 바뀐다. 따로 할 일은 없다.

### 명령줄 사용

```
set PYTHONPATH=src

python -m weather.collect all        # 예보 + 특보
python -m weather.collect forecast   # 예보만
python -m weather.collect warning    # 특보만
python -m weather.scheduler          # 주기 수집
python -m weather.export             # 전체 항로 엑셀
python -m weather.export R1          # 영성 항로만 (설정 파일의 ID 로 지정)
python -m weather.export_web         # web/data/*.json 만 다시 만들기
python -m weather.serve 8080         # web/ 폴더를 띄우는 웹 서버
```

### 수집이 도는 순서

```
weather.collect all
   │
   ├─ grid.load_mask()            바다 칸 목록 (data/grid_mask.json, 한 번만 계산)
   │
   ├─ combined.collect_forecast()
   │     ├─ ECMWF 사이클 확인 → 새 것이면 내려받기, 아니면 저장해 둔 것 재사용
   │     │     └─ 지점 15곳 + 바다 칸 950개를 같은 파일에서 뽑는다
   │     ├─ NOAA 시정 (새 사이클일 때만)
   │     └─ MET Norway 바람 (매번, 앞쪽 시간만 덮어씀)
   │
   ├─ kma.collect_warnings()      기상청 특보
   ├─ db 저장 → 아카이브 정리 → 보존기간 지난 것 삭제
   └─ export_web + grid.build()   web/data/*.json 새로 쓰기
```

`data/source_state.json` 에 마지막으로 처리한 ECMWF 사이클을 적어 둔다.
같은 사이클이면 `data/last_forecast.json` 에 저장해 둔 값을 재사용한다.
(310 MB 를 또 받지 않으려는 것이다.)
